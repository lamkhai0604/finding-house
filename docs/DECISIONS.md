| D-030 | **The browser calls the backend directly** (cross-origin, CORS limited to the frontend's own origin) **instead of Vercel rewriting `/api` to it**. The backend takes the client address from the `CF-Connecting-IP` header only when `CLIENT_IP_HEADER` is configured (on Render), otherwise from the TCP connection. Reasons: through a Vercel rewrite, Render would see Vercel's servers as the client, so the per-address login limit (D-024) would group unrelated users; and Render passes `X-Forwarded-For` through unchanged, so it can be forged, while Cloudflare (in front of every Render service) sets `CF-Connecting-IP` itself. Tokens travel in the `Authorization` header, so CORS needs no cookies or credentials. Cost: one extra preflight request per new kind of API call; the CSP lists the API origin. | Found while preparing T-114; changes the "Vercel rewrites /api" idea Claude described to Khai earlier the same day. | Approved | Claude (technical choice within the approved Sprint 3 plan); reported to Khai 2026-11-05; reversible | NFR-01, D-024, T-114 |
